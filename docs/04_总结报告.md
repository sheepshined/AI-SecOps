## 1. 项目概述

### 1.1 项目定位

本项目参赛课题为 **「AI+安全大模型平台的智能体研究」**，聚焦企业安全运营中心（SOC）的核心痛点：**告警洪水、响应滞后、技能断层**。我们以「大模型 + 规则引擎 + 知识库」三驾马车架构，打造了一套 AI SecOps 智能体平台。

### 1.2 一句话介绍

> 一个能自动从深信服 XDR 拉取告警、调用大模型进行智能研判、结合 CVE/ATT&CK/内部知识库增强结论、并通过智能助理实现"封禁 IP、标记误报、查看态势"等自然语言交互的安全运营平台。

### 1.3 解决的核心问题

| 问题 | 传统方式 | 本平台方案 |
|------|----------|------------|
| 告警洪水（80%+ 误报） | 人工逐条排查 | AI 自动研判 + 加白规则引擎 |
| 研判耗时（15–30 min/条） | 人工分析 + 查资料 | 大模型 + RAG 上下文 ≤ 3 秒 |
| 处置动作分散 | 登录防火墙/EDR 手动操作 | 智能助理一句话 → 自动化执行 |
| 新漏洞响应滞后 | 人工关注漏洞情报 | NVD/CISA/CIRCL 三源自动同步 |
| 学生身份关联难 | Excel 查 IP 对应人 | 上传 CSV 自动导入 → 自然语言查询 |

### 1.4 应用场景

- **高校校园网安全运营**：展示时配置了 XYC（新余学院）的 14 个二级学院 Web 资产，支持「今日受攻击学生」等特色场景
- **企业 SOC 内部演示**：直接对接深信服 XDR 平台，拉取真实告警进行 AI 研判
- **安全培训 / CTF 教学**：造一批演示告警（`seed_malware_alerts.py`），用于攻防复盘训练

## 3. 技术亮点

### 3.1 亮点一：自研 XDR OpenAPI 签名器（零 SDK 依赖）

深信服 XDR 提供 AK/SK 认证 + HMAC-SHA256 签名，我们完整复刻了签名规范：

```
Canonical String = Method + URL Path + Query String + Headers + SignedHeaders + Payload Hash
Payload Hash = 字节排序 + 去空格 + SHA256（深信服非标准实现）
Signature = HMAC-SHA256(SecretKey, "HMAC-SHA256\n" + sign-date + "\n" + SHA256(Canonical))
```

不依赖任何厂商 SDK，仅用标准库 `hashlib` + `hmac` + `binascii` 实现，同时支持「连接码自动解码 AK/SK」的便捷模式。

### 3.2 亮点二：RAG 增强的 AI 研判流水线

研判不是孤立调用 LLM。我们构建了一套轻量但有效的 RAG：

1. **关键词提取**：从告警举证中提取中英文关键词 + IP + ATT&CK ID + CVE ID
2. **同义词扩展**：`sql ↔ 注入 ↔ injection`、`暴力破解 ↔ brute force`、`横向移动 ↔ lateral movement`
3. **双源召回**：从漏洞库（NVD/CISA/CIRCL）和资料库（用户上传）分别打分排序
4. **格式化注入**：Top 3 漏洞 + Top 3 资料 → 2500 字符 → 注入 System Prompt
5. **结果结构化**：LLM 响应中提取 `研判结果: 攻击成功/失败/尝试` 关键字段

相比纯 LLM 裸调用，RAG 增强使研判准确率显著提升（特别是匹配到已知 CVE 的场景）。

### 3.3 亮点三：智能助理双模式架构

- **规则模式（默认，离线可用）**：关键词 → 技能匹配 → 直接查询数据库/执行操作。不消耗 LLM Token，响应毫秒级。
- **大模型模式（增强）**：自然语言 → LLM 理解 → 输出 JSON 命令 → 系统执行。支持复杂多轮意图。

两种模式无缝切换，前端一键开关。JSON 命令协议设计保证了 LLM 输出可被程序化验证后再执行。

### 3.4 亮点四：可扩展技能系统

技能定义为纯 JSON，热加载，无需改代码：

```json
{
  "id": "query_web_asset",
  "trigger_keywords": ["资产", "证书", "WAF"],
  "handler": "query_web_asset",
  "params": [{"name": "domain", "type": "string"}]
}
```

默认内置 4 个技能（封禁、身份查询、受攻击学生、漏洞统计），开发者可自行扩展。

### 3.5 亮点五：漏洞库三源自动同步

接入 NVD API + CISA KEV JSON + CIRCL MISP OSV 三个公开数据源，统一规范化后进入漏洞库，定时调度 + 文件锁保证幂等性。漏洞库同时作为 RAG 知识库的一部分，让 AI 研判能够匹配到最新 CVE。

### 3.6 亮点六：Web 资产真实探测

不是展示静态数据——`probe_asset()` 函数发起**真实** HTTP 请求：

- 正常请求验证业务是否在线
- SQL 注入 payload（`id=1' OR '1'='1`）验证 WAF 是否真正拦截（403/拦截标记 → 视为 WAF 正常）
- `ssl.create_default_context()` + `_create_unverified_context()` 双回退探测证书有效期

### 3.7 亮点七：生产级部署方案

从开发到生产一条路径：

```
start_dashboard.cmd（Windows 一键）
    → DB_USER=xxx DB_PASSWORD=xxx python3 app.py（Linux）
        → gunicorn -w 4 + Nginx 反代 + Let's Encrypt（生产）
            → Docker Compose 容器化（演进方向）
```

API 前缀、数据库配置、调度周期均通过环境变量 / 配置文件管理。⚠️ 但仍有 2 处历史遗留硬编码路径：`build_static.py:4` 的 macOS 输出目录、`app.py:1723` 的 `/private/tmp/pipeline_result.json` 默认路径。

## 5. 问题与经验

### 5.1 踩过的坑

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| MySQL 8.0 下 `1054 Unknown column 'ai_result'` | 旧版用 MariaDB 的 `ADD COLUMN IF NOT EXISTS` 语法，MySQL 静默失败 | 手动 catch 1060 错误（列已存在），继续执行 |
| 批量导入 CSV 身份映射 | 中英文表头不统一（IP/ip/IP地址/src_ip） | `key_map` 同义词匹配表，自动识别 |
| LLM 并发 429 限流 | FastGPT 有 QPS 限制 | 指数退避重试 3 次（实际为 5s / 10s，见 `llm_client.py:115`） |
| 自签 XDR 证书 SSL 握手失败 | 内网环境 CA 不公开 | 降级到 `ssl._create_unverified_context()` |
| Flask debug 模式 + Windows 中文批处理 | `.cmd` 文件 UTF-8 中文注释导致命令解析错 | 批处理保持 ASCII 内容 + CRLF 换行 |
| NVD 无限速 Key 被限流 | 公共 API 免费配额有限 | 支持可选 NVD_API_KEY；降级时跳过失败源 |
| SQLite 迁移到 MySQL 时主键冲突 | 旧代码用自增 int，现用 uuid | db.py 里 `ON DUPLICATE KEY UPDATE` 统一处理 |

### 5.2 经验总结

#### 经验一：单文件 Flask 在 MVP 阶段是最佳选择

传统分层（routes/controller/service/model）在 54 个路由的规模下反而增加了跳转成本。`app.py` 单文件集中管理所有路由，配合 db.py / xdr_pipeline.py 等独立模块，**搜索成本最低、调试链路最短**。等到进入 v2.0 再拆分为 Blueprint 也完全来得及。

#### 经验二：自研而非依赖厂商 SDK

XDR 签名是典型的「厂商私有规范 + 文档不透明 + SDK 依赖重」场景。我们没有直接 `pip install sangfor-sdk`，而是逆向文档 + 抓包 + 反复测试，最终用标准库实现了签名器。**30 行核心签名代码 → 零依赖 → 完全可控**，这一决策在后续调整签名细节时节省了大量时间。

#### 经验三：RAG 可以很轻

我们最初计划接 Chroma 做向量数据库，但实际落地发现「关键词匹配 + 同义词扩展 + 命中数评分」的轻量方案在这个场景下已经足够好。因为安全研判的关键词高度结构化（ATT&CK ID、CVE ID、攻击类型中英文对照），**BM25 + 规则的 Baseline 已经胜过了"接个向量数据库就叫 RAG"的噱头**。

#### 经验四：配置即代码 + 优先级链

我们按运行形态划分了两条配置链：

```
Web 服务：数据库走环境变量（进程级，其次 db.py 默认值）
          XDR 与 LLM 走 JSON 配置文件（data/xdr_config.json、data/assistant_config.json）
命令行：  命令行参数 > .env > 代码默认值（仅 xdr_pipeline.py 的 CLI 分支自行解析）
```

**注意：Web 服务不读 `.env`。** 因此「改了 `.env` 却没生效」是排查时的常见误区——XDR / LLM 凭据要改 `data/` 下的两个 JSON 文件（或通过前端页面）。数据库凭据则通过环境变量注入，同一套代码零修改即可切换开发机 / 测试机 / 生产。

#### 经验五：演示/比赛的 MVP 应该"少即是多"

在最终提交前一周我们做了两次重大功能裁剪：

- **砍掉**：实时网络流量分析（PCAP 解析）—— 太复杂且容易出 bug
- **保留**：XDR 流水线 + AI 研判 + 智能助理 + 漏洞库 + Web 资产 + 身份映射
- **增强**：前端交互细节、一键启动脚本、演示告警造数工具

**能演示跑通的功能 > 10 个半成品**。

| 缺陷 | 严重度 | 计划 |

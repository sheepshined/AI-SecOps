## 5. 代码规范

### 5.1 Python 规范

- **Python 版本**：3.10+，使用 `from __future__ import annotations` 做前向引用
- **类型注解**：函数签名使用 `dict | None`、`list[str]` 等 PEP 604 语法
- **导入顺序**：`标准库 → 第三方 → 本地`，每组空一行
- **字符串**：默认双引号；SQL 语句、日志用单引号
- **异常处理**：顶层路由用 `try/except` + `traceback.print_exc()` 便于调试
- **日志**：`print()` 直接 stdout，Flask `after_request` 统一处理响应

### 5.2 文件头部模板

```python
"""模块说明：一句话职责 + 详细描述。

文件：xxx.py
"""
from __future__ import annotations

import json
import os
from pathlib import Path
from typing import Any, Callable
```

### 5.3 Flask 路由规范

```python
@app.route('/api/xxx', methods=['GET', 'POST'])
def api_xxx():
    """功能描述（给开发者看的 docstring）"""
    data = request.get_json(force=True) or {}
    # 校验
    if not data.get('ip'):
        return jsonify({'error': '缺少 IP'}), 400
    # 业务逻辑
    try:
        result = do_something()
        return jsonify({'ok': True, 'data': result})
    except Exception as e:
        import traceback; traceback.print_exc()
        return jsonify({'error': str(e)}), 502
```

### 5.4 JSON 响应规范

- **成功**：`{"ok": true, "data": {...}}` 或直接返回列表
- **失败**：`{"error": "错误描述"}` + 非 2xx 状态码
- **分页**：当前全部返回全量；后续加 `page/page_size/total`
- **时间**：所有时间用 `'%Y-%m-%d %H:%M:%S'` 字符串格式；`timezone.utc` 统一基准

### 5.5 数据库操作规范

- **所有 DB 操作都应走 `db.py` 封装的函数**，禁止在路由中直接写 SQL
- **upsert 模式**：`INSERT ... ON DUPLICATE KEY UPDATE`，避免重复入库
- **连接管理**：`get_conn()` 返回裸连接，调用方 `try/finally` 或 `with` 模式
- **字符集**：`utf8mb4`，支持 emoji

```python
    ip = request.args.get('ip', '').strip()
```

```python
def _call_my_custom_api(config: dict, messages: list) -> str:

    api_key = config["api_key"]

# 注册到统一入口
def call_openai_compatible(config: dict, messages: list) -> str:
```

### 6.4 修改 XDR 签名算法

深信服签名规则变更时，修改 `xdr_pipeline.py` 中的 `AkskSigner.sign()` 方法。签名计算包含 5 部分：

```
Canonical String =
  HTTP Method + "\n" +
  URL Path（排序+URL转义）+ "\n" +
  Query String（排序+URL转义）+ "\n" +
  Headers（排序后拼接）+ "\n" +
  SignedHeaders + "\n" +
  Payload Hash（特殊规则）

Signature = HMAC-SHA256(SecretKey, "HMAC-SHA256\n" + sign-date + "\n" + SHA256(Canonical))
```

```javascript
// 通用 Fetch 封装（在 app.js 顶部）
async function api(path, opts = {}) {
    const resp = await fetch(path, {
        headers: {'Content-Type': 'application/json'},
        ...opts,
        body: opts.body ? JSON.stringify(opts.body) : undefined
    });
    if (!resp.ok) throw new Error((await resp.json()).error || 'Request failed');
    return resp.json();
}

// 使用

```

## 8. 调试与排错

### 8.1 常见启动错误

| 错误 | 原因 | 处理 |
|------|------|------|
| `1045 Access denied` | MySQL 账号/密码不对 | 检查环境变量；或用 SQL 建账号 |
| `1054 Unknown column 'xxx'` | 旧版本建表漏列 | 手动 `ALTER TABLE alerts ADD COLUMN ...` |
| `pycryptodome not found` | 用连接码但没装 pycryptodome | `pip install pycryptodome` |
| 端口被占用（5000） | 其他进程占用 | `netstat -ano \| findstr :5000` 找到 PID 杀掉 |

### 8.2 告警为空

```bash
# 检查调度器状态
curl http://127.0.0.1:5000/api/xdr/scheduler/status
# 期望 {"running": true, "last_error": null}

# 如果 last_error 有值，多半是 XDR 凭据过期或网络不通
# 注意：XDR 调度器没有重启接口（只有 GET /api/xdr/scheduler/status），需重启进程

# 手动触发一次 pipeline（会立即拉一批真实告警）
curl -X POST http://127.0.0.1:5000/api/xdr/pipeline -H 'Content-Type: application/json' -d '{"count":5}'

# 如果 XDR 平台本身无新告警，造一批演示数据（注意不要与真实数据混淆）
python seed_malware_alerts.py
```

**注意**：`DISABLE_XDR_SCHEDULER=1` 必须设置——否则 `import app` 会启动调度线程并立刻真实拉取 50 条告警并调用大模型。

### 11.2 Docker 部署

```bash
cd security_agent_dashboard
docker compose up -d --build
# 访问 http://127.0.0.1:5000
```

- `docker-compose.yml`：app + MySQL 8（健康检查）+ `./data` 卷持久化 XDR/模型配置；
- 数据库凭据通过 compose environment 注入，**上生产前必须改掉默认密码**；
- Dockerfile 当前用 `python app.py` 启动；生产建议改 CMD 为 `gunicorn -w 4 -b 0.0.0.0:5000 app:app`。

### 11.3 处置安全阀与环境开关

| 环境变量 | 默认 | 作用 |
|----------|------|------|
| `ALLOW_INTERNAL_BLOCK` | 未设 | `=1` 解除内网封禁硬校验（`skills.is_protected_ip` 拦截 RFC1918/回环/链路本地/保留段） |
| `DISABLE_XDR_SCHEDULER` | 未设 | `=1` 时导入 `app` 不启动 XDR 调度线程（测试/离线用） |

### 11.4 LLM 成本日志

每次真实 LLM 调用会追加一行 JSONL 到 `data/llm_usage.jsonl`：`{"ts","model","latency_ms","usage"}`。可用 `python -c "import json;[print(json.loads(l)) for l in open('data/llm_usage.jsonl',encoding='utf-8')]"` 汇总每次研判的 token 与耗时。

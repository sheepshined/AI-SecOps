## 4. 接口测试

### 4.1 接口响应格式验证

**工具**：pytest + requests

```python
# 保存为 tests/test_api.py
import pytest
import requests

BASE = "http://127.0.0.1:5000"

def _ok(resp):
    assert resp.status_code == 200, f"{resp.status_code}: {resp.text[:200]}"

def test_stats_returns_numbers():
    r = requests.get(f"{BASE}/api/stats")
    _ok(r)
    d = r.json()
    for k in ["total", "high", "critical", "open", "false_positive", "blocked"]:
        assert isinstance(d[k], int), f"{k} 应为 int，实际 {type(d[k])}"
        assert d[k] >= 0

def test_alarms_list_structure():
    r = requests.get(f"{BASE}/api/alarms")
    _ok(r)
    alarms = r.json()
    assert isinstance(alarms, list)
    for a in alarms[:3]:
        assert "id" in a
        assert "severity" in a
        assert a["severity"] in ("critical", "high", "medium", "low")
        assert "status" in a
        assert "aiJudged" in a

def test_alarms_filter_severity():
    for sev in ["critical", "high", "medium", "low"]:
        r = requests.get(f"{BASE}/api/alarms", params={"severity": sev})
        _ok(r)
        for a in r.json():
            assert a["severity"] == sev

def test_stats_endpoint_ok():
    for path in ["/api/blocked", "/api/whitelist", "/api/assets", "/api/attack/stats"]:
        r = requests.get(f"{BASE}{path}")
        _ok(r)
```

## 6. LLM 智能助理专项测试

### 6.1 规则模式测试（不依赖 LLM）

> **前置说明**：默认只有 **4 个技能**（`skills.py:15-62`）：IP 封禁、IP 查身份、今日受攻击学生、漏洞每日统计。
> 只有匹配到这 4 个技能触发词之一的输入才走规则模式；其余输入会落到 LLM 分支（需先配好激活模型），未配模型时返回 400「没有激活的模型」。

| 用户输入              | 期望行为                               | 路径 |
| ----------------- | ---------------------------------- | ---- |
| 「封禁 IP 1.2.3.4」   | 创建封禁记录 + 状态更新                      | 规则（`ip_block`） |
| 「查询 10.0.4.21 的姓名学号」 | 查 `identity_db.json` 返回姓名/学号/院系     | 规则（`ip_identity`） |
| 「今天哪个学生受到了攻击」     | 查 identity\_db + alerts 返回姓名/学号/院系 | 规则（`today_attacked_students`） |
| 「最近一周有哪些学生受到了攻击」 | 同上，时间窗放大到 7 天                     | 规则（同上，`_parse_days_from_text`） |
| 「每天拉取了多少漏洞」       | 漏洞库每日统计 + 与告警研判的匹配情况              | 规则（`vuln_daily_stats`） |
| 「今天有多少告警」「当前安全态势」 | 需 LLM 结合 `/api/stats` 数据回答         | LLM |
| 「查看高危告警」          | 需 LLM 理解后回答                        | LLM |
| 「哪些 IP 被封禁了」      | 需 LLM 理解后回答                        | LLM |
| 「关闭告警 ALT-xxx」    | LLM 输出 `{"action":"close_alarm"}` → 执行 | LLM（`app.py:1073-1081`） |
| 「把 ALT-xxx 标记为误报」 | LLM 输出 `{"action":"false_positive"}` → 仅改状态，**不建加白规则** | LLM（与 `/api/alarms/<id>/false_positive` 行为不同，见下方注意） |
| 「ATT\&CK 哪个技术最多」  | 需 LLM 结合 `/api/attack/stats` 回答     | LLM |
| 「切换到告警展示」         | 前端页面跳转，不经过客服端 API                   | 前端 |

> **注意（两条路径行为不一致）**：`app.py:1064-1072` 的 `false_positive` 命令只把告警状态改为 `false_positive`，
> **不会创建加白规则**；而 `POST /api/alarms/<id>/false_positive`（`app.py:488-494`）会创建规则并对所有匹配告警批量加白。
> 测试时需对两条路径分别断言。

### 8.3 文件锁防重入

连续手动触发 3 次 `/api/vulns/update`，期望只有 1 个任务实际执行，后两次返回 409 `已有更新任务在运行`。

**防重入由进程内标志 `_state['updating']` 保证**（`vuln_scheduler.py:158-159`），与文件锁无关。`.vuln_scheduler.lock` 的作用是防止 gunicorn 多 worker 各自启动一个调度线程（`vuln_scheduler.py:236-244`）。

## 1. 系统概述

### 1.1 项目背景

随着企业 IT 基础设施规模持续扩大，传统安全运营中心（SOC）面临三大挑战：

- **告警洪水**：每日万级 XDR 告警中，误报率可达 80% 以上，分析师难以聚焦真正威胁。

- **响应滞后**：人工研判一条告警平均耗时 15–30 分钟，窗口期内攻击者已完成横向移动。

- **技能断层**：高水平 SOC 分析师缺口大，自动化处置能力薄弱。

本项目以「大模型 + 规则引擎 + 知识库」三驾马车，构建一个 **AI SecOps 智能体平台**，目标是将告警研判自动化率提升至 70% 以上，处置响应时间从分钟级缩短到秒级。

### 1.2 建设目标

| 维度        | 指标                             |
| --------- | ------------------------------ |
| 告警自动研判覆盖率 | ≥ 70%（严重度 ≥ medium 的告警）        |
| 平均研判耗时    | ≤ 3 秒/条（不含 LLM 网络延迟）           |
| 告警处置自动化   | 封禁 IP、标记误报、关闭告警可通过智能助理一键完成     |
| 知识库增强研判   | 结合 CVE/ATT\&CK/内部 SOP 提升研判准确率  |
| 真实资产探测    | 支持对 Web 资产进行真实 HTTP/WAF/SSL 探测 |

### 1.3 关键技术选型

| 层次     | 技术                                         | 选型理由                                                   |
| ------ | ------------------------------------------ | ------------------------------------------------------ |
| 后端框架   | Python 3.10+ / Flask                       | 轻量、生态丰富、快速原型迭代；`app.py` 单文件承载所有路由，结构清晰                 |
| 关系数据库  | MySQL 5.7+/8.0+                            | 告警/封禁/加白等结构化数据；支持索引优化查询；mysql-connector-python 官方驱动    |
| 前端     | 原生 HTML/CSS/JS + Lucide Icons              | 零构建、单页应用、Lucide 图标 CDN；不引入 React/Vue 避免构建复杂度           |
| 大模型接入  | OpenAI 兼容协议（FastGPT/DeepSeek/Kimi/MiniMax） | 统一 chat/completions 接口；FastGPT 非标准 API 单独适配；指数退避重试 3 次 |
| XDR 对接 | 深信服 OpenAPI（AK/SK HMAC-SHA256 签名）          | 连接码自动解码 AK/SK；自研签名器不依赖 SDK，最小化依赖                       |
| 漏洞数据源  | NVD API + CISA KEV JSON + CIRCL MISP JSON + OSV.dev（默认关闭） | 公共免费；NVD 可选 API Key 提频；调度器默认 6 小时增量拉取（现值以 `data/vuln_scheduler_config.json` 为准）                   |
| 调度机制   | threading + 文件锁（.lock）                     | Gunicorn 多 worker 下通过文件锁保证唯一性；自研轻量调度器，不引入 Celery       |

### 2.3 线程模型

系统包含 3 类后台线程：

| 线程       | 入口                                        | 触发方式                             | 幂等性保证                           |
| -------- | ----------------------------------------- | -------------------------------- | ------------------------------- |
| XDR 自动研判 | `app.py` 中 `threading.Thread`             | **启动瞬间先拉一次（默认 50 条）**，之后每 60 秒增量拉取 + AI 研判 | 已研判 uuid 集合跳过 LLM；数据库 upsert 覆盖 |
| 漏洞库更新    | `vuln_scheduler.start_update()`           | 每 `interval_seconds` 拉取（默认 6 小时） | 文件锁 `.vuln_scheduler.lock`      |
| 漏洞库调度看门狗 | `vuln_scheduler.ensure_scheduler_alive()` | 检测**漏洞库**调度线程是否存活，挂掉自动重启（XDR 调度器无看门狗） | 文件锁 `.vuln_scheduler.lock`       |

### 3.2 XDR 流水线模块（核心）

**调用链：**

```
run_pipeline(xdr_config, model_config, count)
  │
  ├─ XDRClient.list_alerts()         # POST /api/xdr/v1/alerts/list
  │     └─ AkskSigner.sign()         # HMAC-SHA256 签名
  │
  └─ for each alert_item:
        ├─ XDRClient.get_proof(uuid)  # GET /api/xdr/v1/alerts/{uuid}/proof
        ├─ build_judgment_request()   # 注入 knowledge_context RAG
        ├─ call_model_judgment()      # 调 LLM（带重试）
        ├─ extract_ai_result()        # 正则提取「攻击成功/失败/尝试」
        └─ db.upsert_alarm()          # 保留已有研判结论 + 加白状态
```

**关键设计点：**

1. **连接码自动解码**：深信服 XDR 提供的十六进制连接码（14 段 `|` 分隔），通过 AES-CBC 解密得到 AK/SK，用户只需配置 `XDR_AUTH_CODE`。
2. **自研签名器**：`AkskSigner` 完整复刻深信服 OpenAPI 签名规范（Canonical String + HMAC-SHA256 Header），不依赖官方 SDK。
3. **幂等入库**：`INSERT ... ON DUPLICATE KEY UPDATE` 保证重复拉取不会产生脏数据；已研判告警复用数据库结论，不再消耗 LLM 调用。
4. **RAG 增强**：`knowledge_context` 从漏洞库和资料库中召回 Top N 相关文档，注入 system prompt，提升研判准确率。
5. **确定性预评分（2026-09-28 增补）**：每条告警先与加白规则匹配（`_matches_whitelist`），命中即跳过大模型调用——确定性判断前置，降低成本与误判面（对标 AiSOC 的 deterministic scoring 分层）。
6. **置信度输出（2026-09-28 增补）**：模型按「置信度: 0-100」输出自查把握，随 `ai_confidence` 列入库，供前端与复核排序使用。
7. **处置硬校验（2026-09-28 增补）**：所有封禁入口（路由/技能/LLM 命令）执行前经 `is_protected_ip` 校验，RFC1918/回环/链路本地/保留段一律拒绝，防内网误封；`ALLOW_INTERNAL_BLOCK=1` 可解除。

### 3.3 智能助理模块

**双模式架构：**

| 维度 | 规则模式（默认）                                           | 大模型模式                                |

```json
    {"name": "ip", "type": "ip", "required": true}
```


### 3.4 知识库 RAG 模块

**召回算法：**

```
告警举证数据 ──关键词提取──► tokens
    │                              │
    ├─ 正则：IP / ATT&CK ID / CVE ID
    ├─ 停用词过滤 + 噪声过滤
    └─ 中英同义词扩展（sql↔注入↔injection）
                                   │
                                   ▼
                           漏洞库 + 资料库
                                   │
                              关键词命中数评分
                                   │
                           ┌───────┴────────┐
                           ▼                  ▼
                      Top 3 漏洞          Top 3 资料
                           │                  │
                           └──────┬───────────┘
                                  ▼
                           文本截断（≤2500字符）
                                  │
                                  ▼
                           注入 LLM System Prompt
```

**同义词表示例（关键的跨语言能力）：**

| 中文       | 英文                 |
| -------- | ------------------ |
| SQL / 注入 | sql injection      |
| 暴力破解     | brute force        |
| 横向移动     | lateral movement   |
| 恶意代码     | malware / c2       |
| 凭证窃取     | credential dumping |

### 5.5 XDR 与 AI 研判

| 方法   | 路径                           | 说明                  |

## 6. 核心业务流程设计

### 6.1 XDR 告警自动研判流水线

```
┌─────────────┐    60秒     ┌───────────────┐    POST      ┌──────────┐
│ 后台定时线程 │ ─────────► │ XDRClient     │ ──────────► │ 深信服    │
│             │             │ .list_alerts()│             │ XDR 平台 │
└─────────────┘             └───────┬───────┘             └──────────┘
                                     │ items[]
                                     ▼
                          ┌─────────────────────┐
                          │ for each item:       │
                          │  1. get_proof(uuid)  │
                          │  2. build_judgment   │
                          │  3. call LLM         │
                          │  4. extract_ai_result│
                          │  5. db.upsert_alarm  │
                          └─────────────────────┘
                                     │
                                     ▼
                          ┌─────────────────────┐
                          │ 前端每 30s Fetch 刷新 │
                          │ GET /api/alarms      │
                          └─────────────────────┘
```

### 6.2 告警处置流程

```
分析师点击「封禁」  ──►  POST /api/alarms/<id>/block
                               │
                     ┌─────────▼──────────┐
                     │ 1. 创建 BLOCKED 记录 │
                     │ 2. 状态改为 blocked  │
                     │ 3. db.upsert_blocked│
                     │ 4. refresh_alarms()│
                     └────────────────────┘

分析师点击「标记误报」──► POST /api/alarms/<id>/false_positive
                               │
                     ┌─────────▼──────────────────┐
                     │ 1. 从告警自动提取 src/dst   │
                     │    IP + 端口 + name_pattern │
                     │ 2. 创建 whitelist_rule     │
                     │ 3. _apply_whitelist        │
                     │    _to_alarms()            │
                     │ 4. 所有匹配告警自动 status  │
                     │    变为 false_positive     │
                     └────────────────────────────┘
```

### 6.3 智能助理对话流程

```
用户输入：「封禁 IP 1.2.3.4」

```

## 7. 安全设计

### 7.1 密钥管理

| 类型            | 存储                      | 前端可见性            | 风险控制          |
| ------------- | ----------------------- | ---------------- | ------------- |
| MySQL 账号      | 环境变量                    | 不可见              | 进程级隔离         |
| LLM API Key   | `assistant_config.json` | 脱敏（前4位+\*\*\*\*） | 前端展示脱敏；后端完整使用 |
| XDR 连接码 / AK / SK | `data/xdr_config.json`（Web 写入路径）与 `.env`（CLI 用） | 脱敏（前4位+\*\*\*\*） | 前端展示脱敏；后端完整使用；⚠️ 文件为明文 |
| FastGPT Token | `.env`                  | 不可见              | 文件权限 600      |

### 7.2 反代与 HTTPS

生产部署建议使用 Nginx 反代 + Let's Encrypt 证书：

```nginx
server {
    listen 80;
    server_name dashboard.example.com;
    return 301 https://$host$request_uri;
}
server {
    listen 443 ssl http2;
    ssl_certificate /etc/letsencrypt/...;
    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

### 7.3 已识别风险点

| 风险                     | 现状                      | 缓解                       |
| ---------------------- | ----------------------- | ------------------------ |
| Flask dev server 不适合生产 | `app.run()` 仅用于开发       | 生产用 gunicorn + Nginx     |
| XDR 自签证书跳过校验           | `requests.verify=False` | 内网环境可接受；生产部署应配置 CA       |
| 无认证机制                  | 所有 API 裸暴露              | 生产环境前置 Nginx Basic Auth  |
| `.env` 明文密钥            | 见上方密钥管理                 | `.gitignore` 排除；文件权限 600 |

## 8. 扩展性设计

### 8.1 水平扩展

- Flask → Gunicorn 多 worker（`gunicorn -w 4`）

- 文件锁调度 → Redis 分布式锁

- 漏洞源 `vuln_updater` 已支持三源，新增数据源遵循统一 JSON 格式规范
